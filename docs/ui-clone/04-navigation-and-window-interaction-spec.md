# 桌面端全局导航与窗口交互规范

## 1. 文档目的

本文定义桌面端应用的目标导航模型，统一以下交互：

- 项目任务与会话如何使用工作标签切换。
- 技能中心、设置、定时任务等功能如何作为独立页面打开。
- Windows 最小化、最大化和关闭按钮如何在所有页面保持一致。
- 插件、技能和 Agents 如何作为技能中心内部导航切换。

本文只定义目标体验与验收标准，不代表当前代码已经全部实现。

---

## 2. 核心决策

应用采用“全局应用框架 + 工作标签 + 独立功能页面”的混合导航。

| 层级 | 内容 | 交互形式 |
| --- | --- | --- |
| 全局应用框架 | 工作标签、任务工具、窗口控制按钮 | 始终固定在窗口顶部 |
| 工作区 | 项目中的任务或会话 | 可切换、排序、关闭的工作标签 |
| 独立功能页面 | 技能中心、设置、定时任务 | 覆盖主内容区，不创建工作标签 |
| 页面内部导航 | 插件、技能、Agents | 技能中心内部的轻量导航 |

主要原则：

1. 工作标签只表示用户正在处理的任务或会话。
2. 商店、设置等应用功能不进入工作标签列表。
3. Windows 控制按钮由应用框架统一渲染，任何页面不得自行复制。
4. 独立功能页面打开时，已打开的工作标签继续保留，并作为返回工作区的直接入口。

---

## 3. 信息架构

### 3.1 工作对象

工作标签对应“可持续工作的上下文”，第一阶段仅包含：

- 新建但尚未发送消息的任务。
- 已有消息的任务或会话。
- 正在运行或等待用户操作的任务。

项目继续作为侧边栏中的分组和工作目录上下文。除非未来增加独立的项目总览页面，否则项目本身不单独创建标签；任务标签通过所属项目获得工作目录、终端和文件上下文。

### 3.2 独立功能页面

以下内容不创建工作标签：

- 技能中心。
- 设置。
- 定时任务。
- 其他未来新增的应用级管理页面。

独立功能页面属于应用导航，而不是用户的工作文档。

### 3.3 任务附属工具

以下工具依附于当前任务，不作为应用级页面：

- 打开 VS Code。
- 打开或切换终端。
- 打开项目文件与工作台。
- 查看当前任务活动。

进入技能中心、设置等独立功能页面后，这些任务工具应隐藏；Windows 控制按钮继续显示。

---

## 4. 全局顶部结构

顶部区域固定在主内容区最上方，不随页面内容滚动。

从左到右分为：

1. 工作标签区域。
2. 可拖动窗口的弹性空白区域。
3. 当前任务的上下文工具区域。
4. Windows 最小化、最大化和关闭按钮。

### 4.1 尺寸建议

| 元素 | 目标规格 |
| --- | --- |
| 全局顶部栏高度 | 44–48px，全应用一致 |
| 工作标签宽度 | 默认 160–180px，标题超长时截断 |
| 窗口控制按钮宽度 | 46px |
| 窗口控制按钮高度 | 与顶部栏等高 |
| 可拖动区域 | 除按钮、标签和可交互控件之外的全部空白区域 |

### 4.2 窗口控制规则

- 在工作区、技能中心、设置和定时任务中始终可见。
- 最小化、最大化、还原和关闭行为必须一致。
- 关闭按钮悬停使用 Windows 关闭按钮反馈。
- 最大化后图标切换为“还原”。
- 双击可拖动空白区域切换最大化和还原。
- 交互控件必须标记为非拖动区域，避免点击时拖动窗口。

---

## 5. 工作标签

### 5.1 标签内容

每个任务标签至少包含：

- 任务标题。
- 运行状态指示。
- 错误状态指示。
- 关闭按钮。

可选辅助信息：

- 所属项目名称，放在提示信息或标签菜单中，不与任务标题竞争。
- 未读或等待审批状态。

### 5.2 标签状态

| 状态 | 表现 |
| --- | --- |
| 默认 | 中性文字与透明背景 |
| 悬停 | 浅色背景，显示关闭按钮 |
| 当前工作任务 | 显示选中背景或底部指示线 |
| 独立功能页面打开 | 所有工作标签取消当前选中表现，但保持可点击 |
| 正在运行 | 标题前显示动态状态点 |
| 执行失败 | 标题前显示错误状态 |
| 拖动排序 | 标签浮起并显示目标插入位置 |

### 5.3 标签操作

- 单击：切换到对应任务，并退出当前独立功能页面。
- 中键或关闭按钮：关闭目标任务标签。
- 拖动：调整任务标签顺序。
- 右键：关闭、关闭其他、关闭左侧、关闭右侧、关闭全部。
- 关闭正在运行的任务时：继续使用“保留后台运行”或“停止并关闭”的确认策略。

### 5.4 标签溢出

- 标签过多时允许横向滚动。
- 当前标签切换后必须自动滚动到可见区域。
- Windows 控制按钮和任务工具不得被标签挤出窗口。
- 标签区域在窄窗口下优先收缩，窗口控制按钮保持固定尺寸。

## 6. 独立功能页面

### 6.1 打开规则

用户从侧边栏进入技能中心、设置或定时任务时：

1. 主内容区切换到目标独立页面。
2. 不向工作标签列表添加新标签。
3. 记录进入页面前的当前工作标签。
4. 工作标签继续显示，但不显示任何选中状态。
5. 左侧对应功能入口显示选中状态。
6. 任务附属工具隐藏。
7. Windows 控制按钮保持不变。

### 6.2 返回工作区

用户可以通过以下方式返回：

- 点击任意工作标签，直接进入该任务。
- 点击侧边栏中的任意历史任务，打开或激活对应标签。
- 点击“新建任务”，创建并激活新的工作标签。

独立功能页面不需要额外创建一个全局“返回”标签。

页面内部进入详情时，例如打开某个技能详情，可以使用页面内返回按钮或面包屑返回技能列表；该返回行为不影响工作标签。

### 6.3 空工作区

如果没有任何工作标签：

- 技能中心等独立页面仍可正常使用。
- 顶部工作标签区域保持为空并提供足够拖动空间。
- 点击“新建任务”后创建第一个工作标签并进入工作区。

## 7. 技能中心

### 7.1 页面定位

“技能市场”统一升级为“技能中心”，同时承载：

- 已安装插件。
- 已安装技能。
- 已安装 Agents。
- 第三方技能市场。
- 安装、卸载、审计状态和来源信息。

技能中心是一个独立功能页面，不是工作标签。

### 7.2 内部导航

技能中心使用三个页面内导航项：

- 插件。
- 技能。
- Agents。

导航规则：

- 使用轻量文字或浅色胶囊选中态。
- 语义为页面导航，使用 `aria-current="page"`，不使用可关闭标签语义。
- 切换栏目时不改变全局工作标签。
- 每个栏目分别保留搜索条件、筛选条件和滚动位置。
- 离开技能中心后再次进入，恢复上次访问的栏目。

### 7.3 技能栏目结构

技能栏目按顺序包含：

1. 页面标题和说明。
2. 已安装技能概览。
3. 已安装技能搜索和个人／系统筛选。
4. 第三方技能安全提示。
5. 技能市场搜索与筛选。
6. ClawHub 和 SkillHub 状态。
7. 市场技能列表。

安装或卸载成功后，已安装区域和市场卡片状态必须同步刷新。

---

## 8. 页面状态模型

建议在交互层将“当前工作任务”和“当前应用页面”分开管理。

```ts
type AppSurface =
  | { type: 'work'; taskId: string }
  | { type: 'capability-center'; section: 'plugins' | 'skills' | 'agents' }
  | { type: 'settings'; section?: string }
  | { type: 'scheduled' }

type WorkNavigationState = {
  openTaskIds: string[]
  activeTaskId: string | null
  lastActiveTaskId: string | null
  surface: AppSurface
}
```

关键约束：

- `openTaskIds` 只保存任务或会话。
- 技能中心、设置和定时任务不写入 `openTaskIds`。
- 打开独立功能页面时，`activeTaskId` 可以继续保存，但视觉上不显示任务选中态。
- 返回任务时更新 `surface`，不重新创建已经打开的任务。

---

## 9. 状态切换规则

| 当前状态 | 用户操作 | 目标状态 |
| --- | --- | --- |
| 任务 A | 点击任务 B 标签 | 显示任务 B，标签 B 选中 |
| 任务 A | 点击技能中心 | 显示技能中心，工作标签均不选中 |
| 技能中心 | 点击任务 A 标签 | 返回任务 A，标签 A 选中 |
| 技能中心 | 点击侧边栏任务 B | 激活或创建任务 B 标签并进入任务 B |
| 技能中心／技能 | 点击 Agents | 仍在技能中心，切换到 Agents |
| 技能详情 | 点击页面内返回 | 返回技能列表，不离开技能中心 |
| 设置 | 点击新建任务 | 创建任务标签并进入新任务 |
| 任意页面 | 最小化／最大化／关闭 | 执行窗口操作，不改变页面状态 |

---

## 10. 状态恢复

应用重新启动时分别恢复：

- 已打开的工作标签。
- 工作标签顺序。
- 最近激活的工作任务。
- 退出应用前显示的独立功能页面。
- 技能中心最近访问的内部栏目。

如果恢复的任务已不存在：

- 从工作标签中移除该任务。
- 尝试激活下一个有效任务。
- 没有有效任务时进入新任务空状态。

恢复技能中心或设置时，工作标签仍应在后台恢复，但不显示为当前选中。

---

## 11. 键盘与无障碍规则

- 工作标签使用正确的标签列表语义，并支持左右方向键移动焦点。
- `Ctrl+Tab` 在工作标签之间切换，不进入技能中心内部导航。
- `Ctrl+W` 只关闭当前工作标签，不关闭技能中心或设置页面。
- 页面内“插件／技能／Agents”使用导航语义。
- 所有图标按钮提供可读名称和提示。
- 焦点不得进入窗口拖动区域。
- 键盘焦点样式在浅色背景下必须清晰可见。
- 在 200% 缩放和窄窗口下，窗口控制按钮不得溢出或被遮挡。

## 12. 当前实现与目标差异

| 当前实现 | 目标状态 |
| --- | --- |
| `TabBar` 同时承担工作标签、任务工具、窗口控制 | 应用框架统一承载全局顶部结构 |
| 技能市场通过特殊 `MARKET_TAB_ID` 写入标签状态 | 技能中心作为独立功能页面状态 |
| 进入技能市场后隐藏全局 `TabBar` | 顶部工作标签和窗口控制继续保留 |
| `Market` 页面单独渲染 `WindowControls` | 全应用只渲染一套窗口控制 |
| 插件／技能／Agents 使用页面本地状态 | 保留为内部导航，并持久化最近访问栏目 |
| 终端和工作台可以作为多种标签类型出现 | 第一阶段收敛为当前任务的附属工具或面板 |

## 13. 推荐实施顺序

### 阶段一：统一全局顶部框架

- 在 `AppShell` 中统一渲染顶部框架和窗口控制。
- 移除页面级重复窗口控制。
- 保证所有页面使用相同高度和拖动区域。

### 阶段二：收敛工作标签

- 可见工作标签只展示任务或会话。
- 保留现有关闭、拖动、运行状态和右键菜单。
- 独立功能页面打开时取消任务标签选中表现。

### 阶段三：拆分独立功能页面状态

- 技能中心、设置和定时任务不再加入工作标签列表。
- 分离 `activeTaskId` 与当前应用页面。
- 保留并恢复最近工作任务。

### 阶段四：完善技能中心内部导航

- 保留插件、技能、Agents 的内部导航结构。
- 保存最近栏目、各栏目滚动位置和搜索筛选状态。
- 校正内部详情页的返回逻辑。

### 阶段五：桌面端验收

- 逐页验证窗口按钮、拖动、最大化和还原。
- 验证任务标签与独立功能页面之间的往返。
- 验证后台任务、关闭确认和重启恢复。
- 验证窄窗口、系统缩放和键盘操作。

---

## 14. 验收标准

满足以下条件才视为交互改造完成：

- 所有桌面页面始终显示同一套 Windows 控制按钮。
- 技能中心、设置和定时任务不会出现在工作标签列表中。
- 只有任务或会话显示为可关闭工作标签。
- 打开独立功能页面不会关闭、重建或断开现有任务。
- 点击任意工作标签可以从独立功能页面直接返回任务。
- 技能中心内部可以在插件、技能和 Agents 之间切换。
- 离开并重新进入技能中心后能恢复上次访问栏目。
- 任务工具只在任务上下文存在时显示。
- 标签过多、窗口缩放或最大化时，窗口控制按钮不会被遮挡。
- 关闭运行中任务、恢复标签和后台活动行为没有回归。
